    按 ASIN 检索

    这个数据集（Stanford web-Google，2002 年抓取的 Google 网页图）从头到尾不含网址：875,713 个网页在原始数据里只是匿名数字编号和它们之间的超链接边，没有 URL，也不存在官方的 编号→网址 对照表。界面上显示的「网页 #N」就是数据集里的原始网页编号——不是本项目漏标，而是数据里根本没有网址可标，也不编造。PageRank 的分值是浮点数，经 IEEE-754 保序映射转成 int64 后，8 种自实现排序都能直接用；510 万条边排成 CSR 本身也是一次 40 位键的大排序。
    本页各图按网页在搜索系统里的作用命名：重要性 = PageRank（搜索引擎排序的核心依据，"被高质量网页推荐的程度"）、被链接数 = 入度（多少网页指向它）、外链数 = 出度（它指向多少网页）、链接结构 = 网页之间的链接关系。数据集只含这几类信息，因此界面不虚构"点击量/搜索量"这类原始数据里不存在的指标——只用真实存在的量说话。

    网页重要性排行 Top-100（PageRank）

    按重要性降序——这正是搜索引擎"搜索结果按重要性从高到低显示"的那一步。条长 = 重要性相对第一名；旁边被链接数（多少网页指向它）与外链数（它指向多少网页）。为什么没有网址列？本数据集只提供匿名网页编号（web-Google，2002 年 Google 网页 crawl），不含 URL、也没有官方的 编号→网址 对照表，所以「网页 #N」是数据集原始编号而非网址——无法还原，也不编造。

    重要网页及其邻居（链接关系图）

    重要性前 40 的网页（粉）和它们在抽样边里最常互相链接的邻居（灰）。可拖拽，滚轮缩放。图中标签同样是数据集匿名编号（非网址）。

    被链接数分布（log-log）

    横轴：一个网页被多少个别的网页链接（入度）；纵轴：有多少网页处在这个量级。近似一条直线 = 幂律长尾：少数枢纽被大量网页链接，绝大多数网页只被少数几个链接到——这正是搜索引擎必须做重要性排序的原因。

    被链接数 × 重要性

    正相关但不完全一致：重要性会沿链接传导，被链接数不高的网页也可能因为被重要的网页链接而排名靠前——说明只按"被链接数"排序并不够，PageRank 才是搜索排序的依据。

    网页链接结构（排序后的链接关系片段）

    链接边按（来源页, 目标页）键排序后，同一来源页的出链连成一段，这就是 CSR 的行索引。点 = 抽样里存在的链接。

    应用需求分析（对应评分点 9）

    题目原文："在许多看似无关的领域中，排序是一个重要的子问题"。本系统用同一套自实现排序内核（8 种算法 + AdaptSort）覆盖六个真实数据领域，每个场景共用一份数据契约（postings 键 + 实体台账 + 元数据）与同一套多级键编码方法：

  • 电影（MovieLens 32M）：3.2×10⁷ 条 (movieId, userId, ratingIdx) 打包为 int64 键排序建倒排索引——排序是索引构建的真正瓶颈；
  • 电商（Amazon Electronics 782 万评论）：商品关注度/好评度双模式榜单，ASIN 稠密化=键域变换；
  • 城市骑行（Citi Bike 2019 全年 1279 万次）：站点台账序=真实版"块状近序"，AdaptSort run-merge 路径的现实原型；
  • 搜索（Stanford Web 图 510 万边）：CSR 建图的排序瓶颈 + PageRank 分值经 IEEE-754 保序映射后直接复用整数排序内核；
  • 航班（US DOT 2019）：长尾延误分桶=计数排序的现实用例；
  • 基因组（E. coli K-12 4.64 Mb）：倍增后缀数组每轮对 (rank[i], rank[i+k]) 复合键全量排序——实际 12 轮提前终止（全后缀已区分）。本数据每轮策略均为 S5 基数排序，并不随轮次变化。

    • 系统架构

    C++ 单二进制（排序内核 common/ + AdaptSort + 应用层 app/）── WinSock2 手写 HTTP 服务 ── 浏览器前端（本页面，ECharts 本地化）。数据由 app/pre/pre_<scn>.py 流式预处理：原始数据 → records.jsonl.gz（JSON 交付形态）→ int64 键编码（postings.dat）；排序核心全部为 C/C++ 自实现。

    扩充功能（评分点 10）

  • 外部排序（BSBI）：内存 1/10 限流 → 块内 AdaptSort → k 路堆归并，统计 I/O 块数（sort_demo_app extsort app/data/<scn>）；
  • Top-K 选择对比：堆 O(n log k) vs 快速选择 O(n) vs 全排序 O(n log n)，任意场景可跑（sort_demo_app topk app/data/<scn>）；
  • 多场景扩展框架：新增场景只需一个预处理脚本 + 键位参数（meta.txt），排序内核与 UI 零改动；
  • 基因组子串搜索：O(m log n) 后缀数组二分（六场景总览页演示）。
