    应用需求分析（对应评分点 9）

    题目原文："在许多看似无关的领域中，排序是一个重要的子问题"。本系统用同一套自实现排序内核（8 种算法 + AdaptSort）覆盖六个真实数据领域，每个场景共用一份数据契约（postings 键 + 实体台账 + 元数据）与同一套多级键编码方法：

  • 电影（MovieLens 25M）：2.5×10⁷ 条 (movieId, userId, ratingIdx) 打包为 int64 键排序建倒排索引——排序是索引构建的真正瓶颈；
  • 电商（Amazon Electronics 782 万评论）：商品关注度/好评度双模式榜单，ASIN 稠密化=键域变换；
  • 城市骑行（Citi Bike 2019 全年 1279 万次）：站点台账序=真实版"块状近序"，AdaptSort run-merge 路径的现实原型；
  • 搜索（Stanford Web 图 510 万边）：CSR 建图的排序瓶颈 + PageRank 分值经 IEEE-754 保序映射后直接复用整数排序内核；
  • 航班（US DOT 2019）：长尾延误分桶=计数排序的现实用例；
  • 基因组（E. coli K-12 4.64 Mb）：倍增后缀数组每轮对 (rank[i], rank[i+k]) 复合键全量排序——排序占构造耗时 ~90%，键域随轮次收缩、AdaptSort 策略随之变化。

    • 系统架构

    C++ 单二进制（排序内核 common/ + AdaptSort + 应用层 app/）── WinSock2 手写 HTTP 服务 ── 浏览器前端（本页面，ECharts 本地化）。数据由 app/pre/pre_<scn>.py 流式预处理：原始数据 → records.jsonl.gz（JSON 交付形态）→ int64 键编码（postings.dat）；排序核心全部为 C/C++ 自实现。

    扩充功能（评分点 10）

  • 外部排序（BSBI）：内存 1/10 限流 → 块内 AdaptSort → k 路堆归并，统计 I/O 块数（sort_demo_app extsort app/data/<scn>）；
  • Top-K 选择对比：堆 O(n log k) vs 快速选择 O(n) vs 全排序 O(n log n)，任意场景可跑（sort_demo_app topk app/data/<scn>）；
  • 多场景扩展框架：新增场景只需一个预处理脚本 + 键位参数（meta.txt），排序内核与 UI 零改动；
  • 基因组子串搜索：O(m log n) 后缀数组二分（六场景总览页演示）。
