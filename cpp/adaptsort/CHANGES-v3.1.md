# cpp/adaptsort —— 与 req7 v3 的差异说明（v3.1）

本目录的 `adaptsort.h` / `algorithms.h` / `counters.h` 复制自 `../req7/`（v3，
2026-09-27 验收版），随后为配合统一工程做了如下修改。req7 原件保持 v3 不动，
其验收文档（《第七题-普适排序算法设计与验证.md》《第七题-改进方案与实施记录.md》）
描述的仍是 req7 原件；本文件记录统一版副本的增量改动。

## 改动 1：基数排序数字位宽纳入成本模型（实现 req7 主文档 §11.6 的既定下一步）

**动机**：统一工程的 8 个基础算法（`common/sortcore.h`）中，基数排序是
**按字节 4 趟、桶表 256 项**的实现 —— 与 req7 v3 的 16 位 2 趟 S5 相比，
小规模档（桶表 memset 占主导）明显更快。统一版全矩阵首跑即暴露：
均匀/高斯分布的 n=10³ 档 AdaptSort 落后最优基础算法 **4.7 倍**（决策层
只会 16 位基数，模型正确地预估它不划算，于是退回内省快排，输给 8 位基数）。

§11.6 的实测早已证明"不存在固定最优位宽"（8 位在 n=10⁴ 快 27%~34%、
在泊松 n=10⁵ 慢 1.6 倍），并把"位宽纳入成本模型"列为下一步。本改动即其实现：

1. `algorithms.h`：`radix_sort_lsd` 增加模板参数 `DB ∈ {8, 16}`（默认 16，
   全部既有调用点不变）；
2. 成本模型新增 `CF_RAD8_P`（8 位数字单趟耗时），标定负载与 `CF_RAD_P`
   相同（均匀 [1,10⁶]，全宽多趟取平均），两套系数并存；
3. 决策层规则 6：16 位与 8 位各按 `趟数 × 单趟` 估一遍取最小，再与计数排序
   （CMARGIN）、比较类竞争；选择结果记录进 `last_radix_db()`
   供追踪（CSV strategy 列显示 "S5 基数排序(8位)"）；
4. 切换裕度按模型可信度拆分（原 v3 对计数/基数统一用 MARGIN=1.30）：
   计数排序保持 1.30（(n,k) 双维外推、误差可达 40%），基数排序降为 1.10
   （单趟系数同形态直接实测，趟数由位宽确定性导出，可信度与比较类同级）。
   该拆分使"预测略胜但不足 30%"的小规模格（均匀/高斯 n=10²，绝对差 ~1μs）
   不再被过度保守地留在比较类。计数被选中仍须同时过自身 1.30 总体裕度。

## 改动 2：标定规模补齐 n=10² 档

实验矩阵的最小规模是 10²，而 v3 标定从 10³ 起步 —— n=100 的全部系数靠
"钳位到 n=1000"外推。对基数这类"每趟含固定桶表开销"的策略，该外推把小 n
的单趟成本高估数倍（桶表 memset 占比随 n 缩小而膨胀），8 位/16 位竞争在
n=100 档系统性判反。补齐 `{100, 8轮}` 标定点后（`MAXP=8` 恰好容纳 8 个点），
n=100 的决策系数全部为实测，符合"决策点上的系数是实测而非插值"的既定方法学。

## 改动 3：计数/计时口径对接统一工程

统一版驱动的 `SortStats`（`common/sortstats.h`）与 sb::Counters 桥接：
计时模式 `counters().on=false`（默认），计数模式读 `cmp/mv/peak` 三项；
降序入口 `adapt_sort_desc` 的语义拆为 `adapt_sort + sb::reverse_array`
（反转的移动计数在计数模式下随 swp 计入）。

## 改动 4：修复 est_count 大 k 越界 UB（int64 posting 场景暴露的真 bug）

`est_count` 的锚点定位循环原为 `while (i + 1 < NK && kk > KANC[i+1]) ++i`，
允许 i 到达 NK-1，随后读取 `KANC[i+1]`（constexpr 数组越界 UB）与
`c_v[CF_CNT_K0+i+1]`（越界读到相邻的基数系数），且上端斜率限幅护栏
（`i == NK-2` 分支）此时不生效 —— k 超过最高锚点 KANC[4]=10⁶ 时外推完全失控。
上游 v3 的负载 k 从未超过 10⁶，故从未触发；第 8 点应用的 int64 posting 键
（k = movieId 值域 ≈ 8.8×10¹¹）首次踩中：计数排序被误判为最优，
`counting_sort_range` 按 k 请求 3.5TB 计数数组 → bad_alloc → abort。
修复：锚点定位上限收紧为 `i + 1 < NK - 1`，越界大 k 落入末段区间外推，
斜率限幅 [0.8, 1.2] 使内存护栏按设计生效。复现方式：加载 25M 条
postings 键（k≈8.8×10¹¹）调用 `adapt_sort<long long>`，修复前在决策层
abort（bad_alloc），修复后正确选择 S5 基数排序（16 位 3 趟）并全量有序。

## 验证

改动后的完整验证以统一工程的全矩阵重跑为准（`results/results_cpp.csv`、
`results/c_vs_cpp.md` 第三节 AdaptSort 比值矩阵），对照基线为改动前的
同装置首跑。实测：均匀/高斯的 n=10³/10⁴ 劣势格全部消除（4.7×→1.0×、
1.78×→0.94×），其余各格无可辨回退；**30 格中 28 格 ≤1.07，唯一未达标的是
均匀/高斯 n=10² 两格（2.22×，绝对差 ~1.3μs）**——归因于标定的单发计时
含每运行一次的堆分配开销，对"每趟含固定桶表初始化"的 8 位基数在 n=10²
的稳态成本有 ~2 倍系统性高估，模型如实按其预测留在比较类。该格属于
主文档 §10.3 记录的"决策成本与排序成本同量级"固有极限类别；
若要继续压缩，需把标定装置也改为批量稳态测量（影响全部系数，须重新
执行 calibcheck 类验证，留作后续）。
